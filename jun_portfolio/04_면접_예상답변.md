## Q1. 단순 OLS 의 8.43 %p 가 왜 과대 추정이라고 판단했나요? 윈저화 99% 의 임계치는 어떻게 정했나요?

**hook (v2 §2-2)**: *"신뢰구간이 [2.46, 14.15]로 매우 넓었고, TikTok 의 viral 특성상 ERV 상위 1% extreme(132% 등) 이 평균을 끌어올린 결과였습니다."*

**풀 답변**:

ERV 분포부터 봤을 때 양 꼬리 1% 안에 100%~132% 영상이 섞여 있었습니다. 이게 평균을 끌어올리는 게 OLS 결과의 신뢰구간 폭(약 11.7 %p) 으로 드러났고, 분포 안정성을 회복하는 게 우선이었습니다.

윈저화 임계치 결정은 다음 흐름으로 진행했습니다.

1. ERV 99 percentile 값 확인 → 약 60 %p 수준 (유효 ERV 영상의 일반 범위 상한)
2. 99 percentile 초과 영상의 *원본 데이터* 확인 — 132% 같은 값이 나오는 이유를 검토 (조회수가 매우 적은 영상에서 좋아요·댓글·저장 합이 view 를 넘는 케이스. 데이터 특성 자체)
3. 99% / 99.5% / 99.9% 세 임계치 후보 비교 → 99% 가 신뢰구간을 가장 좁히면서 표본 손실(16건, 약 1%) 도 받아들일 수 있는 수준
4. 윈저화(상위 1% 를 임계치로 cap) 가 trim(상위 1% 를 제거) 보다 표본 보존이라 우선 채택

윈저화 후 신뢰구간 [3.68, 6.35] 로 좁혀졌고, 추정 안정성 (point estimate variance) 도 약 60% 줄었습니다. *"단순 OLS 만 봤다면 잘못된 마케팅 결정"* 이라는 narrative 의 정량 근거가 이 분포 점검에서 시작됐습니다.

## Q2. PSM 으로 인과 보강한 이유는? 다른 인과 추정 기법 (DiD, IV, RDD) 도 검토했나요?

**hook (v2 §2-2)**: *"단순 OLS 의 8.43 만 보고 결론냈다면 두 배 가까이 과대 추정한 권고를 했을 것 — 인과 보강이 분석가의 책임이라는 걸 직접 확인한 경험"*

**풀 답변**:

데이터 구조 상 사용 가능한 인과 추정 기법을 비교한 결과 PSM 이 가장 적합했습니다.

| 기법 | 적합성 | 사유 |
|---|---|---|
| **PSM (Propensity Score Matching)** | ✅ 채택 | 영상 단위 cross-sectional 데이터에 적합. 처치군(K-Beauty) 과 비슷한 통제군(Generic Skincare) 을 1:1 매칭해 ATT 추정 |
| DiD (Difference-in-Differences) | ❌ | 시점 처치 비교 필요. 본 데이터는 단일 시점 (2024.12 수집) 이라 적용 불가 |
| IV (Instrumental Variable) | ❌ | K-Beauty 키워드 사용에 영향을 주면서 ERV 에 직접 영향 없는 도구변수 발굴 어려움 |
| RDD (Regression Discontinuity) | ❌ | 처치 결정의 cutoff (예: 팔로워 N 명 이상이면 K-Beauty 채택) 가 명확하지 않음 |

PSM 매칭 spec:
- Propensity score 모형: Logistic Regression (`treat ~ log_follower + log_view + upload_gap`)
- 매칭 방식: 1:1 Nearest Neighbor + caliper 0.2 × σ(pscore) 제한
- 표준오차: bootstrap (B=1,000)

매칭 후 SMD (Standardized Mean Difference) 검증 결과 모든 공변량이 0.1 이하로 떨어져 매칭 균형이 잘 맞았습니다. 매칭된 양 그룹 (각 약 200건) 에서 ATT = 4.76 %p (p<0.05) 로 OLS HC3 의 5.10 과 일관 (차이 0.34 %p) — robustness 확인됐습니다.

추가로 후속 분석에서 within-influencer Fixed Effect (LSDV + clustered SE) 까지 갔는데, 여기서 selection effect 95% 발견됐습니다 (Q5 참고).

## Q3. 추천 알고리즘 ver.3 의 stability 검증을 1,540 pair 로 한 이유? 단일 selected 결과만 보면 안 되나요?

**hook (v2 §2-3)**: *"ver.3 결과를 stability 검증(1,540 selected pair 비교) 했더니 단일 selected 결과가 lucky case 였고 평균은 무작위 대비 1.25× 에 그쳤습니다."*

**풀 답변**:

처음 ver.3 의 결과 (`selected = ["krystallee2222", "emchu_"]` 기준 Top-10 ER% = 26.51, 무작위 대비 2.32×) 만 보고 끝낼 뻔했습니다. 그러나 *"이 selected 두 명이 lucky 한 케이스라면?"* 의문이 들어 stability 검증을 설계했습니다.

**검증 설계**:
- 56명 인플루언서 중 2명을 selected 로 뽑는 모든 조합 = C(56,2) = 1,540 pair
- 각 pair 마다 ver.3 알고리즘 실행 → Top-10 ER% 계산
- 무작위 baseline: 56명 중 무작위 10명 추출 (10,000번 부트스트랩)
- 비교 metric: 평균 ER%, std, > random 비율, percentile

**결과**:
- 1,540 pair 평균: 15.0 (vs random 11.4)
- std: 6.83 (변동성 큼)
- > random 비율: 61.4% (40% 케이스에서 무작위에 짐)
- 단일 selected (krystallee2222+emchu_) 의 26.51 = **97.7 percentile** (lucky)

→ "Top-10 = 2.32× random" 은 lucky single shot 이고, 알고리즘의 진짜 평균 효과는 1.25× 정도라는 결론.

추가로 mechanism 분해해보니 ER% 가중치가 **47/56 (84%)** 인플루언서에서 의도대로 작동 안 함 (ver.3 ≈ ver.2). 이게 ver.4 재구현의 정량 근거가 됐습니다.

*"단일 결과만 보지 말고 전체 분포를 본다"* 가 stability 검증의 핵심 — 양액펌프 프로젝트의 *"분포부터 본다"* 와 같은 원칙이 추천 알고리즘에도 적용된 사례입니다.

## Q4. ver.3 → ver.4 의 핵심 차이는 뭔가요? 가중치 방식을 어떻게 바꿨나요?

**hook (v2 §2-3)**: *"TF inflation (단어 N번 반복) 을 제거하고 score 단계의 연속 가중치 곱셈(`score = sim × (normalized_ER + 0.1)`) 으로 재구현했더니..."*

**풀 답변**:

ver.3 의 문제는 가중치를 **단어 반복 횟수** 로 표현한 점이었습니다.

```python
# ver.3 (TF inflation 방식)
df['content_v3'] = df.apply(lambda x:
    (x['no.1'] + ' ') * max(1, int(round(x['normalized_ER'] * 3))) +
    (x['no.2'] + ' ') * max(1, int(round(x['normalized_ER'] * 2))) +
    (x['no.3'] + ' ') * max(1, int(round(x['normalized_ER'])))
)
M_v3 = TfidfVectorizer().fit_transform(df['content_v3'])
score_v3 = cosine_similarity(M_v3, M_v3[selected]).mean(axis=1)
```

문제:
1. `int(round(...))` 정보 손실 — `normalized_ER` 이 [0, 1] 연속값인데 정수 반올림 시 `round(0.16 * 3) = 0` → max(1) 발동 → 84% 인플루언서가 동일 (1,1,1) 가중치
2. TF (term frequency) 만 N배 — 단어 N번 반복하면 IDF 는 동일, TF 만 inflate 되어 의미 왜곡

ver.4 재설계:

```python
# ver.4 (score 단계 연속 가중치)
df['content_v4'] = df['no.1'] + ' ' + df['no.2'] + ' ' + df['no.3']  # 단순 결합
M_v4 = TfidfVectorizer().fit_transform(df['content_v4'])
sim = cosine_similarity(M_v4, M_v4[selected]).mean(axis=1)
score_v4 = sim * (df['normalized_ER'] + 0.1)  # 핵심: TF-IDF 후 score 단계 가중치
```

**핵심 변경**:
- TF inflation 제거 (단순 토픽 결합)
- 가중치를 score 단계로 이동 (`sim × (normalized_ER + 0.1)`)
- `+0.1` epsilon 으로 ER%=0 인플루언서가 score=0 되어 임의 배제 방지 (ver.3 의 max(1) 안전장치 의도 보존)

**정량 비교 (1,540 pair)**:

| Metric | ver.3 | ver.4 | 개선 |
|---|---:|---:|---:|
| 평균 ER% | 15.0 | **39.1** | +24.1 |
| × random | 1.25× | **3.25×** | — |
| > random 비율 | 61.4% | **100%** | — |
| Precision@10 (실제 ER% 상위 10명 중 추천 일치) | 20% | **60%** | — |

Paired t-test (v4 - v3): t=122.80, p<0.0001 → 모든 selected 조합에서 ver.4 가 ver.3 능가.

## Q5. within-FE 분석에서 selection effect 95% 라는 건 무슨 의미인가요? OLS·PSM 의 4.76~5.10 %p 결과는 무효인가요?

**hook (v2 §4 한계)**: *"OLS·PSM 의 4.76~5.10%p 효과의 약 95% 가 인플루언서 selection effect 라는 추가 발견"*

**풀 답변**:

within-influencer Fixed Effect (FE) 결과는 *"같은 인플루언서 안에서 K-Beauty / non-K-Beauty 영상 비교 시 효과는 통계적으로 유의하지 않다 (+0.24%p, p=0.75)"* 입니다. OLS·PSM 결과를 무효로 만드는 게 아니라, **두 결과의 의미가 다르다**는 점을 명확히 해야 합니다.

| 추정 | 의미 | 적용 시나리오 |
|---|---|---|
| OLS HC3 (+5.10) | "조회수·팔로워 비슷한 영상 끼리 비교 시 K-Beauty 효과" | 광고 단가 산정 (영상 단위) |
| PSM ATT (+4.76) | "영상 특성이 비슷한 K-Beauty vs Generic Skincare 1:1 매칭 시 효과" | 보수적 인과 추정 (하한) |
| within-FE (+0.24) | "같은 인플루언서 가 K-Beauty vs non-K-Beauty 영상 만들 때 차이" | *키워드 자체* 의 한계 효과 |

**해석**:
- 마케팅 부서 가 *"K-Beauty 인플루언서를 신규 시딩하면"* 의 효과는 OLS·PSM 의 4.76~5.10%p 가 적정 — 이건 selection 포함된 *비즈니스 의사결정 관점* 의 효과
- 동일 인플루언서가 *"K-Beauty 키워드를 추가로 쓰면"* 의 효과는 within-FE 의 +0.24%p — 이건 *키워드 자체의 marginal* 효과
- 두 추정 차이 (4.86%p) = selection effect = **K-Beauty 키워드를 쓰는 인플루언서들이 원래부터 ERV 가 높은 사람들**

→ 마케팅 시사점: *"인플루언서 선정 > 키워드 선택"*. 이게 추천 알고리즘 ver.4 가 핵심 솔루션이 된 인사이트입니다.

**한계**:
- dual 인플루언서 (K-Beauty + non-K-Beauty 둘 다 만든 사람) 가 30~42명 (전체의 75%) — 표본 작아 검정력 일부 제한
- K-Beauty 전용 인플루언서 (within variation 없음) 의 효과는 measure 불가
- 단일 시점·단일 데이터셋 — 다른 기간으로 일반화 시 재검증 필요

자세한 수치 변천 + 어디서 어느 수치 쓸지 가이드: [`docs/refactor/14_kpremium_number_history.md`](../docs/refactor/14_kpremium_number_history.md).

## Q6. 1만뷰당 47,600~51,000원 의 환산 — 참여 1건당 100원 가정의 근거는?

**hook (v2 §3)**: *"시나리오 민감도(100/300/1,000원) 도 함께 제공해 마케팅 부서의 budget 시나리오에 직접 적용 가능하게 했습니다."*

**풀 답변**:

100원 가정은 **CPE (Cost Per Engagement, 참여 1회당 마케팅 비용) 의 보수적 하한** 입니다. 업계 자료 조사 결과:

| 플랫폼 | 일반 CPE 범위 | 출처 |
|---|---|---|
| TikTok 인플루언서 마케팅 (한국) | 100~500원 | 인플루언서 단가 자료 (2024) |
| YouTube 인플루언서 (Shorts) | 200~800원 | 동급 비교 |
| Instagram Reels | 150~600원 | 동급 비교 |

100원 = 보수적 하한 (실제 마케팅 단가의 대부분이 더 비쌈). 단가가 비쌀수록 *K-Beauty 키워드 효과의 경제적 가치도 비례해 커짐*.

**시나리오 민감도** (PSM 하한 4.76 %p 기준):

| CPE 가정 | 1만뷰 가치 | 의미 |
|---|---:|---|
| 100원 (하한) | 47,600 원 | 보수적 시나리오 |
| 300원 (중간) | 142,800 원 | 일반 |
| 1,000원 (상한) | 476,000 원 | 프리미엄 단가 |

마케팅 부서가 자체 *내부 단가* 로 재환산 가능하도록 식 자체를 노출:

```
1만뷰당 추가 가치 = (10,000 / 100) × effect(%p) × CPE(원)
                = 100 × 4.76 × CPE
                = 476 × CPE
```

**한계** (정직히):
- ERV 가 *직접 매출* 이 아닌 *참여 행동* 만 측정 — 실제 구매까지 가는 funnel 은 미측정
- TikTok → Amazon 의 attribution (구매 출처 추적) 데이터 없음
- 본 환산은 *"참여 가치를 마케팅 비용으로 환산했을 때의 정량적 비교 기준"* 까지가 한계

## Q7. K-Beauty 키워드 정의가 분석 단계마다 바뀌었는데 (4 단어 → 3 단어 → wonyoung 제외), 일관성이 깨지지 않았나요?

**hook (v2 §1)**: *"K-Beauty 키워드를 쓰는 인플루언서들이 원래부터 인기 있는 사람들일 가능성을 통제해야 했습니다"*

**풀 답변**:

분석 단계마다 키워드 정의를 의도적으로 좁혀가며 robustness 를 검증했습니다.

| 단계 | k_keyword 정의 | 의도 |
|---|---|---|
| 초기 (`tiktok_statistic_analysis.ipynb`) | `["kbeauty", "korean", "wonyoung", "korea"]` (4 단어) | 광범위 매칭 — K-Beauty 관련 콘텐츠 모두 포착 |
| 중간 (`statistic_analysis_1228`) | `["kbeauty", "korean", "korea"]` (wonyoung 제외) | 장원영 개인 효과가 K-Beauty 일반 효과를 흐릴 가능성 의심 |
| **메인** (`without_wonyoung_main`) | `["kbeauty", "k-beauty", "koreanskincare"]` (3 단어, paper 적인 정의) | wonyoung 정식 제외 + 비교 그룹 정밀화 (`non_k_skincare = [glassskin, skincareroutine, ...]`) |

각 정의에서도 같은 within-FE 분석 → robust 한 selection effect 95% 패턴:
- 4 단어 정의: OLS 5.02 → FE 0.24 (selection 95.3%)
- 3 단어 정의: OLS 4.15 → FE -0.85 (selection 100%+)

→ *결과 robustness 확인 + 가설 강화* 의 의도적 변형이지, 분석 일관성 깨진 게 아닙니다. 자세한 트레일: [`docs/refactor/14_kpremium_number_history.md`](../docs/refactor/14_kpremium_number_history.md) 의 "수치 진화 단계".

**왜 이렇게 했나** — 단일 키워드 정의로만 분석하면 *그 정의에 의존한* 결과일 위험이 있어, 의도적으로 정의를 바꿔가며 패턴이 일관되는지 (robustness) 확인하는 게 분석가의 의무라고 봤습니다. *"같은 발견을 다른 정의에서도 재현했다"* 가 인과 보강의 또 다른 layer 입니다.
